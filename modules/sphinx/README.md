# Sphinx

Generate project documentation with Sphinx and MyST Markdown. Sphinx is selected by default in the bundled template and works without the Python feature; [Pyproject][pyproject] supplies its development dependencies. [GitLab][gitlab] can add build/publication jobs.

## Questions and choices

| Answer | Decision |
| --- | --- |
| `sphinx_api_packages` | Which available Python packages need generated API documentation. Asked only when the host supplies packages; all available packages are selected by default. |
| `sphinx_needs` | Whether to enable Sphinx-Needs for requirements tracking; defaults to false. |
| `sphinx_needs_pages` | When Needs is enabled, select requirements, architecture, implementation, and verification pages; all four are selected by default. |

## After generation

Replace the TODO in `doc/notes.md` and write content for any selected Needs pages. Review API package selection and documentation metadata. Keep README toctree markers when using the README as the landing page; the index also works without a generated README.

Install the generated project's development dependencies (`python -m pip install --group dev`, adding `--editable .` for an installable distribution), then build with:

```shell
make -C doc/sphinx html SPHINXOPTS='-W --keep-going'
```

Open `doc/sphinx/_build/html/index.html`. See [Sphinx's documentation](https://www.sphinx-doc.org/en/master/) for authoring/build details.

## Reuse reference

Supply `sphinx_inputs` after including the module; see the [module guide][module-guide] for shared rules.

| Input | Type | Standalone fallback and role |
| --- | --- | --- |
| `enabled` | bool | `true`; direct activation. The bundled host uses the Sphinx feature. |
| `repository_name`, `owner_name` | str | `My Repository`, empty; direct documentation metadata. |
| `year` | int | Current year; direct metadata override. |
| `has_readme`, `has_license` | bool | `false`; direct switches for index links. The bundled host checks Core's file manifest. |
| `python_packages` | list[str] | Empty; available API choices. The bundled host derives them from generated Python package files. |
| `api_packages` | list[str] | All available `python_packages`; question default override. |
| `needs` | bool | `false`; question default. |
| `needs_pages` | list[str] | `requirements`, `architecture`, `implementation`, `verification`; question default. |

`sphinx.vars` exposes merged settings with answered `api_packages`, `needs`, `needs_pages`, and the effective year.

When enabled, `files` owns `doc/sphinx/{conf.py,index.md,Makefile,make.bat}` and `doc/notes.md`. API package selection adds `doc/api.md`; Needs selection adds `doc/<page>.md` for each selected page. API/build output is generated by Sphinx, not hand-edited.

The module emits ignore patterns to [Core's `core.gitignore`][core] and dependency entries to [Pyproject's `pyproject.dev_dependencies`][pyproject]. It has no receiving targets. A custom host must supply the dependency receiver and suitable install/runtime wiring if it wants those integrations.
